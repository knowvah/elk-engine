# T4 — Corpus census

**Agent:** typescript-pro · **Commit:** `feat(corpus): classify the elk-models corpus`

## Context
The conformance unit is the algorithm (D1); the sweep (T8) needs every model's id, source file,
and effective root algorithm. elk-models at `ac5af2ba` holds 898 distinct model ids (D3):
examples 45, tests 193, tickets 110, realworld 550 (each realworld model as `.json` + `.elkt` +
`.elkg`). T3's oracle parse mode turns any model into ELK JSON without layout.

## Task
A script that parses every model through the oracle (parse mode), classifies each with a pure
function, and writes the committed census.

## Write-set
`tools/corpus/census.ts`, `test/corpus/census.test.ts`, `test/corpus/census.json` (generated by
the script, never hand-edited).

## Interface contract (output, consumed by T8, T9)
```ts
interface Census {
  modelsCommit: string; elkCommit: string; count: number;
  models: CensusModel[];               // sorted by id, ids unique
}
interface CensusModel {
  id: string;                          // D3, e.g. "tickets/layered/546_borderGaps"
  folder: 'examples' | 'tests' | 'tickets' | 'realworld';
  source: 'json' | 'elkt';             // D3 choice
  formats: string[];                   // all extensions present, sorted, e.g. ["elkg","elkt","json"]
  parse: 'ok' | 'error';
  nodes: number; edges: number; ports: number; labels: number; maxDepth: number;
  declaredAlgorithms: string[];        // normalized full ids, sorted, unique
  rootAlgorithm: string;               // declared on root, else "org.eclipse.elk.layered"
}
```
Normalization: strip a leading `org.eclipse.elk.` or `elk.` then prefix `org.eclipse.elk.`
(values seen at planning: `layered`, `elk.layered`, `org.eclipse.elk.layered`, `stress`,
`box`, `fixed`, `rectpacking`). Counts for a `parse: 'error'` model are `0`.

## Specification
- `npx tsx tools/corpus/census.ts --write` writes the file; without `--write` it prints a diff
  summary and exits 1 if the file would change.
- Oracle outputs go to a scratch dir under `$ELK_ORACLE_DIR/census/`, never into the repo.
- Classification (`classifyModel(parsedJson, id, formats)`) is pure and exported for tests.

## Acceptance criteria
- Given the pinned clone and built oracle, when the census runs, then `count` is 898,
  `count === models.length`, and ids are sorted and unique.
- Given a realworld model with `.json`, `.elkt`, `.elkg`, then `source` is `"json"` and
  `formats` is `["elkg","elkt","json"]`.
- Given a fixture with no `algorithm` key, then `rootAlgorithm` is `org.eclipse.elk.layered`;
  given a root with `elk.stress`, then `org.eclipse.elk.stress`.
- Given a fixture with two nesting levels, then `maxDepth` is 2 and counts include nested elements.
- Given the committed `census.json` and no clone, then `modelsCommit` equals
  `test/corpus/manifest.json` `commit` and `elkCommit` equals `tools/oracle/ELK_COMMIT`.

## Quality bar
README gates. Fixture-based tests for every classify branch; clone-dependent tests skip with the
pinned sha in the message (existing pattern). If any model has `parse: 'error'`, journal the ids
(an `.elkt` that ELK's `GraphFromFile` can read but Xtext standalone cannot is STOP 5).
