# T9 — Parity report

**Agent:** typescript-pro · **Commit:** `docs(parity): add generated per-algorithm parity report`

## Context
The conformance unit is the algorithm (D1). T8 wrote one verdict per case to the local sweep
cache. plantuml-ts commits a generated `docs/parity-report.md` with one row per diagram type
(`~/git/knowvah/plantuml-ts/docs/parity-report.md:1-20` for tone; its empty-cell vocabulary
"names why it is empty" is the model). TS columns stay empty until TS layouts exist.

## Task
Generate `docs/parity-report.md` from `results.jsonl` + `summary.json`.

## Write-set
`tools/corpus/parity-report.ts`, `test/corpus/parity-report.test.ts`, `docs/parity-report.md`
(generated, never hand-edited).

## Read-set
- `../decisions.md#d9--parity-report`, `#d4--verdicts`
- `../batch-4/T8-sweep.md#interface-contract-output-consumed-by-t9`
- `test/corpus/census.json` (folder facet counts) · `docs/conformance.md:1-20` (doc style)

## Specification
- Header: `<!-- GENERATED by tools/corpus/parity-report.ts — do not edit by hand -->`, SPDX line,
  ELK commit, models commit, total cases, wall time rounded to the minute. **No timestamps.**
- Matrix: one row per algorithm id (sorted); columns: cases per tier (native / retarget /
  generated), then verdict counts `ok / throws / nondeterministic / timeout / oracle-error`,
  then `TS conformant` = `n/a (no TS port yet)`.
- A second table: native-tier models per elk-models folder per algorithm (from the census).
- List `parseErrors` ids, if any.
- `npx tsx tools/corpus/parity-report.ts --write` writes; without `--write`, exit 1 when stale.

## Acceptance criteria
- Given a results fixture, then the rendered matrix has one row per algorithm with counts that
  sum to the fixture's cases.
- Given the same inputs rendered twice, then the outputs are byte-identical.
- Given the real sweep, when the report is written, then every algorithm from
  `--list-algorithms` has a row, and no cell is blank (an empty cell names why).
