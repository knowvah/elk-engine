# deferred-bundles-acceptance: mission brief (issue #88)

## Objective

Roadmap row 11 ended with a **Proposed** ADR (`docs/architecture/deferred-bundles-adr.md`) recommending no-go for all three
deferred algorithm bundles. On 2026-11-14 the maintainer accepted it **amended** (comment on #88): `alg.libavoid` is out of scope;
`alg.graphviz.dot` and `alg.graphviz.layouter` are **in scope**, ported faithfully with `GraphvizTool`'s process replaced by an
injected runner, so `@knowvah/dot-engine` can supply it through an adapter outside this package. On 2026-11-23 the maintainer
confirmed "good to go" and relabelled #88 `queue:ready`. This mission records that ruling everywhere the scope is stated, and
changes the bundle table so the two Graphviz bundles can be ported. It ports nothing
([D0](decisions.md#d0-scope-the-acceptance-is-step-1-of-95)).

Exit (#88):

- The ADR reads **Accepted, amended**, with a `## Ruling` section and current consequences; its Proposed analysis stays as history
  ([D1](decisions.md#d1-the-adr-keeps-its-analysis-and-gains-a-ruling)).
- `## AD-17` is appended to `plans/elk-engine-skeleton/decisions.md`
  ([D2](decisions.md#d2-ad-17-records-the-ruling-verbatim-in-substance)).
- CLAUDE.md, `docs/architecture/inventory.md` and `docs/architecture/port-map.md` state the new scope
  ([D4](decisions.md#d4-claudemd-inventory-and-port-map)).
- `IN_SCOPE_SUFFIXES` holds the two Graphviz suffixes, `bundle-deps.json` is regenerated by script with exactly two new keys, and a
  new fitness block pins them ([D3](decisions.md#d3-the-bundle-table-adopts-both-graphviz-bundles-now)).
- Comments on #88 and #95; queue gates 1-7 green and journaled; one squashed commit on the base with `Refs: #88`;
  `plans/roadmap.md` gains `## Revision <date> (deferred-bundles-acceptance)`.

**Not in this mission** ([D5](decisions.md#d5-out-of-scope)): any port of either Graphviz bundle (#95 steps 2-3); the runner API
(#95 step 4, with the maintainer); the adapter and knowvah/dot-engine#220 (#95 step 5); building Graphviz jars in the oracle or

any change under `src/`, to a landed ref, vector, golden or expected value, to an oracle patch or to `ELK_COMMIT`.
