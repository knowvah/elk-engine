# Evidence: alg.libavoid, alg.graphviz.dot, alg.graphviz.layouter (T1, deferred-bundles-adr DB5)

Gathered 2026-11-13 by the executor, for [the ADR](../../docs/architecture/deferred-bundles-adr.md). Every finding names the
command that produced it or a `file:line` at the pin. Nothing here was copied from the planning note; where a planning number
differs, the difference is stated. No oracle, JVM, Graphviz or libavoid binary was run (DB7).

Rows are cited as `LA-n` (`alg.libavoid`), `GD-n` (`alg.graphviz.dot`), `GL-n` (`alg.graphviz.layouter`) and `S-n` (shared by
all three).

## How to re-run

```sh
E=../elk                                             # ELK checkout; HEAD is b715fb10, past the pin
PIN=8aaa3c145c2a18a38aabbc725aa3791ddc517a76         # AD-2, tools/oracle/ELK_COMMIT
P=plugins/org.eclipse.elk
M=../../eclipse-elk/elk-models                       # HEAD ac5af2ba, the commit test/corpus/manifest.json pins
D=../dot-engine                                      # read only; HEAD 9c7c65b6
THREE="$P.alg.libavoid $P.alg.graphviz.dot $P.alg.graphviz.layouter"
```

The Java is read with `git -C $E show $PIN:<path>` and searched with `git -C $E grep … $PIN -- …`, because the checkout's
HEAD is past the pin. `git -C $E log --oneline 8aaa3c14..HEAD -- $THREE` prints nothing: no commit after the pin touches the
three bundles.
