# canonical-nan: mission brief (issue #72)

## Objective

The maintainer ruled on #53 (2026-11-13) that the port has one canonical NaN form, `Double.doubleToLongBits`
(`7ff8000000000000`), for every layout comparison. The JVM gives a computed NaN either sign bit (`7ff8…` or `fff8…`)
depending on interpreted or compiled code, so raw NaN bits cannot be reproduced against the oracle. The loops sweep (7g),
`LayeredCompoundVectors` (7h) and `ForceVectors` (8b) already hash NaN canonically. This mission moves every other layout
recorder, sweep hasher and TS comparison helper to the canonical form on both sides, documents the rule in
`docs/conformance.md`, and adds a fitness test so a raw-NaN encoder cannot come back
([D0](decisions.md#d0-the-ruling-this-mission-executes)).

Exit (#72):

- `docs/conformance.md` has the rule next to the non-finite numbers row (line 169): the two JVM encodings, the sign bit, the
  #53 evidence, the canonical form, and that every non-NaN value keeps its raw IEEE bits ([D6](decisions.md#d6-docs)).
- The audit table (T1) lists every site that encodes a layout double as bits, with its class before and after. Every layout
  site encodes NaN canonically ([D1](decisions.md#d1-what-counts-as-a-layout-comparison),
  [D2](decisions.md#d2-the-canonical-form-on-each-side)). JDK shim vectors stay raw.
- Each changed TS encoder has a unit test that `7ff8…`, `fff8…` and payload NaNs encode alike and non-NaN values keep
  their raw bits ([D4](decisions.md#d4-the-proof)). `test/architecture/canonical-nan.fitness.test.ts` guards both sides
  ([D5](decisions.md#d5-the-fitness-test)).
- Every changed recorder and sweep was rerun. Refs change only on NaN-bearing values, each journaled under #72; the
  planning prediction is no ref change at all ([D3](decisions.md#d3-guarded-recorders-keep-their-guard),
  [D7](decisions.md#d7-regeneration-and-evidence)).
- Queue gates 1-7 green and journaled; one squashed commit on the base; `plans/roadmap.md` gains
  `## Revision <date> (canonical-nan)`; `.agent-notes/canonical-nan.md` is written.

**Not in this mission:**

- How the port computes NaN, any `src/` file, any JDK shim vector (`JavaVectors.java`, `CoreJdkVectors.java`, the
  `hash.json`, `numeric.json`, `lang.json`, `text.json` rows).
- Removing a recorder's NaN guard so it can record NaN rows (D3). The NaN coordinates themselves (#56 item 5, #147).
- #135 (`AlgCommonVectors.java` under `-XX:hashCode=2`) and #143 (recorder splits), though they touch the same files.
- Any oracle patch, `ELK_COMMIT` change, write to `~/git/knowvah/elk`, or the translated `docs-site/` pages.
