# T13 — TS emitter, `melk:generate`, `LabelManagementOptions`

**Agent:** typescript-pro · **Commit:** `feat(T13): emit typescript from the melk model`

## Context
Last generator stage (AD-12). The emitted TS mirrors the generated Java class by class and member by
member (`../elk-oracle/plugins/*/src-gen/**` is the shape reference): bundle class with option
constants, private `_DEFAULT`/`_LOWER_BOUND`/`_UPPER_BOUND`/`_DEP_` constants in Java textual order,
and `apply(registry)`; algorithm classes with `ALGORITHM_ID`, support constants, nested
`<Name>Factory`, `apply`. Generated files follow C6. This task commits only
`LabelManagementOptions.ts`; `CoreOptions.ts` is T14.

## Task
TDD.
1. **Import map** (`imports.ts`): Java FQN → TS module path. `org.eclipse.elk.<rest>.<Class>` →
   `src/<rest>/<Class>.ts` (AD-7); `java.util.EnumSet` → `src/java/util/EnumSet.ts`;
   `java.lang.*` boxed classes and `Integer.MAX_VALUE` → `src/java/lang/{JavaClass,JavaInteger}.ts`;
   nested types per C3 (`org.eclipse.elk.core.util.BoxLayoutProvider.PackingMode` →
   `src/core/util/PackingMode.ts`); interface tokens per T8. Relative `.js` import specifiers as in
   the rest of `src/`.
2. **Emitter** (`emit.ts`): from a `ResolvedBundle` (T12) produce TS text:
   - header comment `// GENERATED by tools/melk from tools/melk/sources/<Name>.melk — do not edit`
     after the SPDX line; `/** @see <bundle>/src-gen/<path>.java */` on each class;
   - `IProperty<T>` constants via the mission-2 `Property` constructor (`src/graph/properties/Property.ts:20-100`),
     `Math.fround` for float literals, expressions translated from the C5 AST
     (`.class` → class/token per T8, `EnumSet.of`, `new KVector(…)`, static calls);
   - `apply(registry)` with the builder chains in the Java order; held-back registrations (C1)
     omitted, each replaced by a one-line comment naming the pending type;
   - static field order identical to the Java (ES static initialisers run in textual order).
   Output is formatted with prettier's API (dev dependency) so `format:check` passes.
3. **Generate** (`generate.ts`): `generate({ bundles?, write })` returns `Map<outputPath, text>`;
   CLI writes files and takes optional bundle names (`npm run melk:generate -- Labels`).
   `package.json` script `"melk:generate": "tsx tools/melk/generate.ts"`. The bundles emitted in
   mission 3 are Core and Labels (default when no names are given); the others are resolved
   (proving the model) but not written. `emitBundle` accepts test-only options: `outputDir` (where
   the file will live, for relative import paths) and `importOverrides` (FQN → module path), used
   by T17 to emit held-back algorithm classes against stub providers.
4. **Recorder** (`test/melk/recorder.ts`): a TS `ILayoutMetaDataProvider.Registry` that records calls
   and encodes values per C4 (doubles via `src/java/lang/DoubleToString.ts`, classes via
   `simpleNameOf`), producing objects comparable to `metadata.json` (i).
5. Run `npm run melk:generate -- Labels` to write `src/core/labels/LabelManagementOptions.ts`
   (Core cannot be emitted yet: `LayoutMetaDataService` and `IndividualSpacings` arrive in T14).

## Acceptance criteria
- Given `LabelManagementOptions.ts`, when `new LabelManagementOptions().apply(recorder)`, then
  `recorder.calls` deep-equal `metadata.json` (i) for `org.eclipse.elk.core.labels.LabelManagementOptions`.
- Given `generate({ bundles: ['Labels'], write: false })`, then the text equals the committed file
  byte for byte (freshness, C6).
- Given the emitted file, then `npm run format:check` and `npm run typecheck` pass, and the file
  starts with the SPDX line followed by the `GENERATED by tools/melk` header.
- Given a float literal default in any bundle's emitted text (resolved, not written), then it is
  emitted as `Math.fround(<literal>)`.
