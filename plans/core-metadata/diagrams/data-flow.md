# Data flow — core-metadata

## 1. Generation and verification

How a `.melk` file becomes committed TS, and the three checks against the JVM (C4, C6).

```plantuml
@startuml
actor Developer
participant "melk:generate" as gen
participant "parser" as parser
participant "model" as model
participant "emit" as emit
database "src/core/**\n(generated TS)" as ts
database "metadata.json\n(JVM, frozen)" as golden
participant "vitest" as test

Developer -> gen : npm run melk:generate
gen -> parser : tools/melk/sources/<Name>.melk
parser --> gen : MelkFile AST (hard error on unknown form)
gen -> model : resolve ids, groups, types,\ndefaults, dependencies
model --> gen : registry calls\n(pending types skipped, C1)
gen -> emit : model + import map
emit -> ts : CoreOptions.ts, LabelManagementOptions.ts\n(header: GENERATED by tools/melk)

test -> model : resolve all 13 .melk
test -> golden : (i) providers
test -> test : model calls == (i)
test -> ts : apply(recordingRegistry)
test -> test : recorded calls == (i) minus pending
test -> ts : LayoutMetaDataService.getInstance()\n+ LabelManagementOptions
test -> test : service dump == (ii) minus pending
test -> gen : generate in-process
test -> test : output == committed file (freshness)
@enduml
```

## 2. Service start-up at runtime

What happens on the first `LayoutMetaDataService.getInstance()` (C8).

```plantuml
@startuml
participant Caller
participant "LayoutMetaDataService" as lmds
participant "CoreOptions" as co
participant "Registry (inner)" as reg
participant "LayoutOptionData" as lod

Caller -> lmds : getInstance()
alt no instance yet
  lmds -> lmds : new LayoutMetaDataService()\n(initElkReflect)
  lmds -> co : new CoreOptions()
  lmds -> co : apply(new Registry())
  loop each option, category, dependency
    co -> reg : register(...) / addDependency(...)
    reg -> lod : store by id (+ legacy ids)
  end
  note right of co : no fixed/box/random\nalgorithms until mission 5 (C1)
end
lmds --> Caller : instance
Caller -> lmds : registerLayoutMetaDataProviders(new LabelManagementOptions())
@enduml
```
