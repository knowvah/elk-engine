# Core Metadata Slice + `.melk` Codegen — Mission Brief (roadmap mission 3)

## Objective

Port the `core` metadata layer: `core.data` (option, category and algorithm data, the
`LayoutMetaDataService`, the deprecated-option replacer, content assist), the remaining
`core.options` enums, `core.labels.ILabelManager`, and the `core.util`/`core.validation` types they
import. Build the `.melk` → TS generator under `tools/melk/` (AD-12) and commit its output for the
core bundle (`CoreOptions.ts`, `LabelManagementOptions.ts`). Every generated value is proven against
a JVM dump of the oracle (`test/golden/refs/java/metadata.json`) written **before** the generator
(AD-13): the generator's model is checked for all 13 `.melk` files, the TS registry for the core
bundle. Registrations that need a not-yet-ported class (the fixed, box and random providers and
`TopdownSizeApproximator`) are held back until mission 5 ([C1](decisions.md#c1--pending-types)).
Nothing is exported from `src/index.ts` (AD-14).

## Quality gates

Agents run their own tests + `npm run typecheck` + `npm run format:check`. The orchestrator runs,
after every batch:

```bash
npm run format:check                                # exit 0
npm run typecheck                                   # exit 0
npm run coverage                                    # exit 0; 90/90/90/90 over src/** + tools/melk/** (after T9)
java tools/vectors/JavaVectors.java test/golden/refs/java \
  && tools/vectors/graph-vectors.sh test/golden/refs/java \
  && git diff --exit-code test/golden/refs/java/    # frozen vectors unchanged
tools/vectors/metadata-vectors.sh test/golden/refs/java \
  && git diff --exit-code test/golden/refs/java/metadata.json   # after T7: byte-identical
git show --name-only --format= HEAD                 # ⊆ the task's write-set
grep -L 'GENERATED by tools/melk' <changed .ts/.java files> \
  | xargs lizard -C 10 -a 5 -T nloc=30 -w           # complexity; generated files skipped (C6)
```

Parallel agents never run `npm run coverage` (shared `coverage/` dir); the orchestrator does.
Generated files are written only by `npm run melk:generate`, never by Write/Edit (C6).

## Stop conditions — halt, journal, wait for the user

1. A file outside the current task's write-set needs changing.
2. The same gate check fails twice in a row.
3. A change would contradict C1–C10 ([decisions.md](decisions.md)), AD-1…AD-15, M1–M8, D1–D10, or
   the conformance-corpus decisions.
4. AD-13: an existing assertion, vector or golden would have to change — any byte diff in the
   existing `test/golden/refs/java/*.json`, or in `metadata.json` once T7 has landed.
5. AD-9: the work seems to need OpenJDK source, or Guava source beyond its Javadoc.
6. T7: the oracle or its generated classes cannot be loaded from the oracle jars / p2 cache, or a
   value has no encoding in the agreed format (C4).
7. A generator result differs from the JVM dump and the cause cannot be named after the diagnosis
   budget (mechanism, `file:line`, ruled out). Never edit the golden to match.
8. The pending-types rule (C1) would skip anything beyond 3 algorithms + 1 dependency in Core, or
   anything in the other 12 `.melk` files.
9. The parser meets a `.melk` construct outside the agreed expression forms (C5) that cannot be
   added as a table entry.
10. A hand-ported file cannot meet the complexity limits (500 lines, 30 NLOC, CCN 10, 5 params)
    without changing method boundaries beyond translation-rules §6 (`LayoutOptionData` is likely).
11. A ported JUnit case can only pass by changing its assertion or dropping it (the two cases
    deferred by C10 excepted).
12. A method or API the Java does not have is needed, beyond type guards, nested-type aliases (C3)
    and the `string` debug folder (C8).
13. T14 does not converge after 3 revisions: the three mutually importing files will not load or
    typecheck together, or ES module evaluation order breaks static initialisation.
14. The work seems to need a runtime dependency or a non-EPL-compatible dev dependency.
15. `npm test` exceeds ~60 s total.

## Push-forward — decide and journal

- `tools/melk/` internals: module split, AST node names, error text, CLI flags — as long as the
  interface contracts in the task files hold.
- `metadata.json` layout beyond the C4 value encoding (key names, provider-entry order); the call
  order inside an entry always follows the JVM.
- The exact `GENERATED by tools/melk` header wording and how the gate detects it.
- T17's provider-import mocking and temp emit directory (under `test/`, gitignored).
- Private helpers inside ported classes; TS-forced splits per translation-rules §6.
- `initElkReflect` registrations of Java collection classes, mapped per AD-10 (journal each).
- A 1–3 line pre-existing-violation fix in a file already being touched (grep references first).
- Test names, commit messages, journal wording, `.agent-notes/core-metadata.md` entries.
