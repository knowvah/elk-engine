# Architecture Decisions — elk-engine skeleton

All decisions are **locked**. If an implementation contradicts one, STOP
and log to `decision-journal.md`.

## AD-1: Java is the spec
Port every branch, keep method boundaries, preserve side-effect order, no
optimizing or simplifying. When in doubt, read the Java; still in doubt,
keep Java behavior and journal the question. On divergence, instrument the
oracle and dump values before hypothesizing.

## AD-2: Pin ELK master 8aaa3c14
`$ELK_SOURCE_DIR` (default `../elk`) at
`8aaa3c145c2a18a38aabbc725aa3791ddc517a76` (0.13.0-SNAPSHOT, 2026-08-05).
Chosen over the 0.12.0 release because the oracle will be rebuilt with
seams anyway. Upgrading ELK is a future roadmap mission.

## AD-3: Oracle built from source with a patch series
- `tools/oracle/build.sh` creates a **detached git worktree** of
  `$ELK_SOURCE_DIR` at `$ELK_ORACLE_DIR` (default `../elk-oracle`) at the
  sha in `tools/oracle/ELK_COMMIT`, applies `tools/oracle/patches/*.patch`
  in lexical order with `git am`, then runs ELK's own Maven/Tycho build:
  `-P elk-meta install` (melk compiler), then the default profile with
  tests skipped.
- The patch series is **empty in this mission**. Text-sizing
  normalization seams arrive later as numbered patches, each paired with a
  TS-side seam and a journal entry.
- `tools/oracle/harness/ElkOracle.java` reads ELK JSON, runs
  `RecursiveGraphLayoutEngine`, writes layout JSON (batch mode, one JVM).
- Requires Maven ≥ 3.9 and JDK 21 (fallback JDK 17, as ELK CI uses).
- elkjs is **not** an oracle (it cannot carry our patches; GWT emulation
  differs from the JVM).

## AD-4: Conformance bar
Exact: element ids, element counts, edge-section topology, bend-point
counts, non-numeric values. Numeric coordinates/sizes: absolute tolerance
**1e-6**. Last-ulp `Math.*` differences between JVM and V8 go to a
known-divergences list (created when first needed).

## AD-5: Goldens and corpus
- Curated oracle outputs committed under `test/golden/refs/elk/` with a
  `_meta.json` (`elkCommit`, `patches`, `modelsCommit`). CI needs no JVM.
- Full-corpus sweeps are local only (later mission).
- elk-models at `$ELK_MODELS_DIR` (default `../../eclipse-elk/elk-models`),
  pinned `ac5af2ba511c0037e4f347e8bd91f013950951c7` in
  `test/corpus/manifest.json`; not vendored.
- When an oracle patch changes output, refs are regenerated by script
  (never hand-edited) and the regeneration is journaled with the patch id.

## AD-6: Toolchain
TypeScript **7.0.2** (`tsc` is the native compiler), vitest **5.0.x**,
`@vitest/coverage-v8` 5.0.x, esbuild 0.28.x, tsx, `@types/node`. ES2022,
`module`/`moduleResolution` NodeNext, `strict`. Node ≥ 22 (volta 26.3.1,
as dot-engine). typedoc does not support TS 7 yet — the docs mission adds a
TS 6 alias then; not needed now.

## AD-7: Module layout and naming
`src/` mirrors Java packages with `org/eclipse/elk/` stripped:
`org.eclipse.elk.alg.layered.p1cycles.GreedyCycleBreaker` →
`src/alg/layered/p1cycles/GreedyCycleBreaker.ts`. **One class per file,
file named exactly as the Java class (PascalCase)** — a deliberate
deviation from kebab-case for traceability, documented in CLAUDE.md. Java
runtime shims live under `src/java/<package>/` (e.g.
`src/java/util/Random.ts`). Every ported symbol carries
`/** @see <bundle>/src/<path>.java */` (shims cite the Javadoc spec URL).
Tests colocated as `<Name>.test.ts`.

## AD-8: Fitness functions
- Allowed imports between `src/` bundle directories are derived from each
  bundle's `META-INF/MANIFEST.MF` `Require-Bundle`, committed as
  `test/architecture/bundle-deps.json`; an algorithm may never import
  another algorithm unless Java does. `src/java` is importable from
  everywhere and imports nothing from ELK directories.
- Every code file (`.ts`, `.java`, `.sh`, `.mjs`) under `src/`, `test/`,
  `tools/` carries `SPDX-License-Identifier: EPL-2.0`.
- `src/` is browser-safe: no Node built-ins, no `process.env`.
- No module-level mutable `let` in `src/` outside a reviewed allowlist.

## AD-9: Java shims from specs, never OpenJDK source
`java.util.Random`, `Collections.shuffle`, `Math.round`, `floorDiv`/
`floorMod`, `(int)` casts, int32 arithmetic, `Double.compare` are
implemented from the **Javadoc-specified algorithms**. OpenJDK is
GPLv2+CE — reading or copying its source into an EPL-2.0 codebase is
forbidden. Exactness is proven against JVM-generated vectors
(`tools/vectors/JavaVectors.java`). Java `long` → `bigint` only where
values can exceed 2^53; document each such site.

## AD-10: Collection iteration order
- `LinkedHashMap`/`LinkedHashSet` → `Map`/`Set`.
- `EnumMap`/`EnumSet` → ordinal-ordered structures.
- `HashMap`/`HashSet` iterated over **value-hashed keys** (String, Integer,
  …) must reproduce Java iteration order — a `JavaHashMap` shim is added
  when the first such site is ported (not in this mission).
- Iteration over **identity-hashed** keys is non-deterministic in Java
  itself: journal the site, port with insertion order.
- Guava → small local helpers; never a dependency.

## AD-11: ElkGraph model (future mission)
EMF-generated `ElkNode`, `ElkEdge`, `ElkPort`, `ElkLabel`,
`ElkEdgeSection`, `ElkBendPoint` become plain TS classes keeping the Java
accessor names (`getChildren()`, `getX()`/`setX()`,
`getProperty(IProperty)`). No EMF notifications, adapters, or reflection.

## AD-12: `.melk` metadata (future mission)
A `.melk` → TS generator under `tools/melk/` emits `*Options.ts` and
metadata providers; output committed; verified by a test against a JSON
dump of the oracle's `LayoutMetaDataService`.

## AD-13: Tests are immutable spec commitments
Expected values come from the oracle, JVM vectors, or the Java source
**before** the implementation is written. Once written, an assertion is
frozen: a failing test means the implementation is wrong. If a test can
only pass by changing its assertion (or a vector/golden), **STOP**, journal,
wait for the user. Port the Java JUnit tests alongside the code they test.

## AD-14: Public contract
The ElkGraph object model (AD-11) plus `ElkGraphUtil` factories is the
public API. ELK JSON is an I/O adapter (needed for the oracle round-trip).
Any idiomatic wrapper is a separate later layer. The first npm publish
freezes this surface. In this mission `src/index.ts` exports nothing
public; `src/java/*` are internal.

## AD-15: Naming and rename safety
Package `@knowvah/elk-engine`; GitHub `knowvah/elk-engine`. The working
directory will be renamed: all scripts and docs use repo-relative paths;
external directories come from `ELK_SOURCE_DIR`, `ELK_ORACLE_DIR`,
`ELK_MODELS_DIR` with defaults relative to the repo root. Library code
never reads env vars (AD-8); only `tools/` and `test/` do.

## AD-16: Exception policy (approved by the user 2026-10-15)

Amends M5 (`plans/java-foundations/decisions.md`), D10 (`plans/elkgraph-model/decisions.md`) and AD-14.
Context: the graph-text follow-ups of 2026-10-15 added Java-named shims for JVM-raised exceptions nothing
catches (`StringIndexOutOfBoundsException`, the `checkCast` `ClassCastException`); the user asked whether
errors should be idiomatic TypeScript rather than identical, and that "similar errors" stay catchable by
parent-class handlers. Audit at that date: within each family the Java inheritance holds
(`NumberFormatException` → `IllegalArgumentException`, the three index exceptions, Gson's
`JsonParseException` and `IOException` families, Xtext's `ValueConverterException`), but of the 29
exception classes the 19 family roots extend `Error` directly (2 of them port-local); Java's `Exception` /
`RuntimeException` layers are missing, and `ArithmeticException extends RangeError` (M5) sits outside the
Java chain.

### AD-16a: Ported core keeps Java's error conditions and the Java chain

- Which input fails, and at which step, is Java's (an oracle-visible behaviour; AD-13 applies).
- Every exception ELK, Xtext, EMF or Gson declares, throws explicitly or catches keeps its Java class and
  its whole Java parent chain. The JS `Error` stands in for `Throwable`.
- `src/java/lang/Exception.ts` (`extends Error`) and `src/java/lang/RuntimeException.ts`
  (`extends Exception`) are added. Unchecked exceptions extend `RuntimeException` (or their Java parent
  below it); checked ones (`IOException`) extend `Exception`.
- **User choice: the Java chain wins over JS built-ins.** `ArithmeticException extends RuntimeException`, no
  longer `RangeError`. Where a class could have a JS built-in parent or its Java parent, it takes the Java
  parent.
- A ported Java `catch (Exception e)` or `catch (RuntimeException e)` stays a catch-all, because D10's
  `TypeError` (Java's NPE) is not under `RuntimeException`. A narrower Java catch becomes an `instanceof`
  check on the Java class.

### AD-16b: No new shims for JVM errors nothing catches

- A JVM-raised exception that no in-scope code catches (null dereference, a failed cast, a JDK
  bounds check) uses the plain JS error (`TypeError`, `RangeError`) in new code; tests compare when it
  happens, not its class. D10 (NPE → `TypeError`) is the model.
- Existing shims stay and join the chain (no retrofit): `ClassCastException`,
  `StringIndexOutOfBoundsException`, `ArithmeticException`, `checkCast`.

### AD-16c: Idiomatic errors belong to the public layer (AD-14)

- The later idiomatic wrapper exposes one library hierarchy under a base class (name decided with that
  layer), with family subclasses that follow the Java grouping, so a parent handler catches similar
  errors. Each wrapper error keeps the core error as `cause`. The core never throws wrapper errors.

### Implementation step (separate, not yet done)

- Add `Exception`, `RuntimeException` (with tests); re-parent the 18 Java-named classes that extend `Error` or
  `RangeError` directly to their Java parents (the 9 family subclasses follow) (all Xtext ones checked against Xtext 2.36.0: `RuntimeException`; ELK's
  `JsonImportException`: `RuntimeException`); port-local errors (`SyntaxFailure`,
  `ElkGraphSerializationError`) stay `Error` subclasses unless a Java counterpart is named.
- Frozen assertions that encode `ArithmeticException extends RangeError` and must be rewritten under this
  decision (AD-13; the user approves the list when the step runs): `src/java/lang/JavaMath.test.ts:100-101`,
  `src/java/lang/Int32.test.ts:66-67`, `src/java/lang/Int64.test.ts:104`,
  `src/java/lang/ArithmeticException.test.ts:23`. `JavaMath.test.ts:54` is unaffected (`round` throws a
  port-local `RangeError`, not a Java exception).
- Update `docs/translation-rules.md` §6.7, the "checked exceptions" row and the AD range in `CLAUDE.md`, and
  add a fitness test that every class named after a Java exception extends its Java parent.
