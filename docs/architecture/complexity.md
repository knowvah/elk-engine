# Complexity gate

`npm run complexity [file|dir ...]` (default `src`) measures **every** TypeScript function against
the project limits and exits 1 on any violation. It needs the `lizard` executable
(`pip install lizard`) and exits 2 without it.

| Metric         | Limit (violation is strictly greater) |
| -------------- | ------------------------------------- |
| NLOC           | 30                                    |
| CCN            | 10                                    |
| Parameters     | 5                                     |
| Lines per file | 500                                   |

Skipped: `*.test.ts`, `src/core/options/CoreOptions.ts`, and any file whose first lines carry
`GENERATED by tools/melk`.

## Why not plain `lizard`

Plain `lizard -C 10 -a 5 -T nloc=30` exits 0 while silently dropping or truncating functions. Known
triggers on lizard 1.22.2 (each has a fixture in `test/architecture/fixtures/complexity/`):

- a function-typed constructor parameter (`f: (key: K) => V`) hides every later member, `#private`
  methods included (`src/emf/ecore/util/EcoreEMap.ts` lost about a third of its functions);
- a `new X()` default parameter hides the constructor and everything after it;
- a regex literal containing a quote, inside a function, hides everything after it;
- a parameter typed `readonly (A | B)[]` hides that function;
- a parenthesised call (`x = (f(a) + 1) * 2`) and an optional call (`f?.(x)`) end the enclosing
  function early, so its NLOC and CCN are far too low;
- `<` right after `:` in an object literal or ternary reads as a generic and inflates the function
  (a false positive; reported as lizard sees it, per the hook).

## How it works

1. **Inventory** (`inventory.ts`): `oxc-parser` (explicit devDependency, MIT) parses each file; every
   function declaration, expression, arrow, method (`#private`, getters, setters, constructors)
   becomes an entry with name, start line, end line and AST parameter count.
2. **Direct pass** (`measure.ts`): lizard runs once over sanitized copies (`#name` becomes `_name`).
   A lizard function counts as the inventory entry only if its start lies between the declaration
   line and the body line **and its end line equals the AST end line**, which rejects truncated
   results.
3. **Snippet fallback**: each remaining function becomes a standalone `function f(p0, p1) { ... }`
   (parameters replaced by placeholders, regex literals by `/x/`) and a single lizard run measures
   all snippets. The snippet keeps the body byte-for-byte, so NLOC and CCN agree with the direct
   pass (checked on all 1240 directly measured functions of `src/`: 1239 identical).
4. **Stripped snippet**: if that fails, the snippet is retried with TypeScript-only syntax, `?.(`
   and expression parentheses blanked to spaces (line structure, hence NLOC, is preserved).
5. **AST measurement** (`ast.ts`): last resort. NLOC and CCN are counted from the AST with lizard's
   rules (nested functions and template literals excluded, `??` counts twice, `?.` once). This is
   approximate and listed separately under `measured by AST only`.

The parameter count is the larger of lizard's and the AST's. Lizard skips files whose content
duplicates an earlier file, so every temporary file ends with a unique comment.

## Reading the output

```text
function violations (1)
  src/java/lang/DoubleCompare.ts:9  compare  CCN 11 > 10  [direct]
files: 191  functions: 1876  measured directly: 1240  via snippet: 632  via stripped snippet: 3  via AST only: 1  skipped files: 153
```

`[direct]`, `[snippet]`, `[snippet-stripped]` and `[ast]` name the tier that produced the numbers.
A lizard exit 0 is meaningless without a plausible function count; this tool prints the AST count.
