# Contributing

Read [Overview](/guide/overview) and [Translation rules](/guide/translation-rules) first. The Java
at the pinned commit is the specification; when in doubt, read the Java.

## Gates

Run these before every commit. Each must pass.

| Command                | Checks                                                        |
| ---------------------- | ------------------------------------------------------------- |
| `npm run format:check` | Prettier formatting                                           |
| `npm run typecheck`    | TypeScript type check (native `tsc --noEmit`)                 |
| `npm test`             | The vitest suite, including the golden suite                  |
| `npm run coverage`     | The suite with 90% lines, branches, functions, and statements |

Requires Node 22 or newer. Install dependencies with `npm ci`.

## Tests are immutable

Expected values come from the oracle, JVM vectors, or the Java source before the implementation is
written (AD-13). Once written, an assertion is frozen: a failing test means the implementation is
wrong.

If a test can only pass by changing its assertion, a vector, or a golden, stop and record the case
in the mission's decision journal. Do not loosen a tolerance, delete a case, or regenerate a ref to
get green. Golden refs are regenerated by script, never by hand.

## Workflow

1. Create a feature branch, for example `feature/<short-description>`.
2. Write commit messages as [Conventional Commits](https://www.conventionalcommits.org), for example
   `feat(java): add JavaHashMap`. Subjects are lowercase and at most 72 characters.
3. Open a pull request against `main`. CI lints the pull request title as a Conventional Commit.
4. Commits must be signed; the repository ruleset requires it.
5. Pull requests are merged with a merge commit.

Every code file carries an SPDX header, `// SPDX-License-Identifier: EPL-2.0`. A fitness test
enforces it. Dependencies must be compatible with EPL-2.0.

## Documentation commands

| Command                | Purpose                                              |
| ---------------------- | ---------------------------------------------------- |
| `npm run docs:dev`     | Start the documentation site with live reload        |
| `npm run docs:build`   | Build the site; a dead internal link fails the build |
| `npm run docs:preview` | Serve the built site locally                         |

Most reference pages include files from `docs/`. Edit the file in `docs/`, not the page under
`docs-site/`. PlantUML diagrams in the included files are rendered to SVG and committed under
`docs-site/public/diagrams/`.

## External directories

Scripts and tests locate sibling checkouts through environment variables. Defaults are relative to
the repository root. Only `tools/` and `test/` read these variables; code in `src/` never does.

| Variable         | Default                        | Content                                              |
| ---------------- | ------------------------------ | ---------------------------------------------------- |
| `ELK_SOURCE_DIR` | `../elk`                       | Eclipse ELK Java source at the pinned commit         |
| `ELK_ORACLE_DIR` | `../elk-oracle`                | Detached worktree and built oracle                   |
| `ELK_MODELS_DIR` | `../../eclipse-elk/elk-models` | The elk-models corpus, pinned in the corpus manifest |

The oracle build needs Maven 3.9 or newer and JDK 21 (JDK 17 as a fallback). See
[Conformance](/conformance) for the oracle procedure.
