# Основы Java

Результаты ELK зависят от поведения среды выполнения Java: переполнения 32-битных целых, округления `float`,
порядка итерации `HashMap`, последовательностей `Random` и преобразования чисел в текст.
Миссия java-foundations (завершена 2026-10-11) поставила шимы, воспроизводящие это поведение,
и записанные на JVM векторы, которые его подтверждают.

Шимы реализуются только по спецификации из Javadoc. Исходный код OpenJDK не читается и не
копируется (AD-9). Каждый шим проверяется по векторам, сгенерированным на настоящей JVM.

## Шимы

| Область          | Расположение             | Содержимое                                                                                                                                                                                               |
| ---------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Числа и текст    | `src/java/lang/`         | `Int64`, `Float32`, `JavaString`, `JavaInteger`, `JavaDouble`, `DoubleToString`                                                                                                                          |
| Math             | `src/java/lang/JavaMath` | `l2i` (`(int)` от `long`)                                                                                                                                                                                |
| Исключения       | `src/java/lang/`         | Шесть классов исключений                                                                                                                                                                                 |
| Коллекции        | `src/java/util/`         | `HashStrategy`, `JavaHashMap`, `JavaHashSet`, `PriorityQueue`                                                                                                                                            |
| Замены для Guava | `src/guava/`             | 20 файлов: `Lists`, `Iterables`, `Iterators`, `Strings`, `DoubleMath`, `Joiner`, `Splitter`, `Range`, `Table`, `ImmutableMap`, `ImmutableSet`, `Sets`, `Maps`, `HashBiMap`, `Multimap` и пять реализаций |

`Math.log10` не нуждается в шиме: нативная функция V8 совпадает со всеми 1264 записанными строками.
Guava никогда не является зависимостью; `src/guava/` содержит небольшие локальные вспомогательные функции.

## Векторы JVM

Векторы записываются `tools/vectors/JavaVectors.java` (и `GuavaVectors.java` для Guava
33.3.0-jre). Они заморожены: при перегенерации получаются побайтово идентичные файлы.

| Группа    | Строки или скрипты                                                                                        |
| --------- | --------------------------------------------------------------------------------------------------------- |
| Числа     | `l2i` 78, `Float32` 2704, double в float 72, `log10` 1264, деление на ноль 40, `Int64` 4056               |
| Хеш       | `String.hashCode` 229, `Double.hashCode` 65, `doubleToLongBits` 65, `Integer.reverse` 36, хеш KVector 256 |
| Текст     | `Double.toString` 14,939, `parseDouble` 96, `Integer.valueOf` 33                                          |
| Random    | `setSeed` в середине последовательности: 4 seed по 25 операций                                            |
| Коллекции | 1206 скриптов `HashMap`, 1172 скрипта `HashSet` и 231 скрипт `PriorityQueue`                              |
| Guava     | 1518 скриптов, 25,611 шагов                                                                               |

## Известные ограничения

- Порядок записей `HashMap` на JVM, ключи которых имеют одинаковые хеш-коды и не являются `Comparable`,
  определяется идентичностью объектов и не может быть воспроизведён. Случаи соответствия, которые от него
  зависят, требуют записи об известном расхождении.
- Скрипты `HashMap` и `HashSet`, зависящие от идентичности, пропускаются в векторах, а
  скрипты `PriorityQueue(Collection)` пропускаются, потому что в ELK для них нет вызывающего кода.
- `Sets.newTreeSet` возвращает снимок. Живой шим `TreeSet` нужен до портирования
  `ScanlineOverlapCheck` и `ScanlineConstraintCalculator`.
