# 기여하기

먼저 [개요](/ko/guide/overview)와 [번역 규칙](/guide/translation-rules)(영어)을 읽으십시오. 고정된 커밋의 Java가 명세이며,
확실하지 않으면 Java를 읽으십시오.

## 게이트

커밋하기 전에 매번 실행하십시오. 모두 통과해야 합니다.

| 명령                   | 검사 내용                                                |
| ---------------------- | -------------------------------------------------------- |
| `npm run format:check` | Prettier 포맷                                            |
| `npm run typecheck`    | TypeScript 타입 검사(네이티브 `tsc --noEmit`)            |
| `npm test`             | 골든 스위트를 포함한 vitest 스위트                       |
| `npm run coverage`     | 라인, 분기, 함수, 구문 90% 커버리지 기준을 적용한 스위트 |

Node 22 이상이 필요합니다. 의존성은 `npm ci`로 설치하십시오.

## 테스트는 변경할 수 없습니다

기대값은 구현을 작성하기 전에 오라클, JVM 벡터, 또는 Java 소스에서 가져옵니다(AD-13). 한번 작성한 단언(assertion)은
고정됩니다. 테스트가 실패하면 구현이 잘못된 것입니다.

단언, 벡터, 골든을 바꿔야만 통과하는 테스트라면 멈추고, 그 사례를 미션의 결정 저널에 기록하십시오. 통과시키려고 허용
오차를 느슨하게 하거나, 케이스를 삭제하거나, 참조를 다시 생성하지 마십시오. 골든 참조는 스크립트로 다시 생성하며,
손으로 만들지 않습니다.

## 작업 흐름

1. 기능 브랜치를 만드십시오. 예: `feature/<short-description>`.
2. 커밋 메시지는 [Conventional Commits](https://www.conventionalcommits.org) 형식으로 작성하십시오. 예:
   `feat(java): add JavaHashMap`. 제목은 소문자로 쓰며 72자를 넘기지 않습니다.
3. `main`을 대상으로 풀 리퀘스트를 여십시오. CI가 풀 리퀘스트 제목을 Conventional Commit으로 린트합니다.
4. 커밋은 서명되어야 합니다. 저장소 룰셋이 이를 요구합니다.
5. 풀 리퀘스트는 머지 커밋으로 병합합니다.

모든 코드 파일에는 SPDX 헤더 `// SPDX-License-Identifier: EPL-2.0`가 있습니다. 핏니스 테스트가 이를 강제합니다.
의존성은 EPL-2.0과 호환되어야 합니다.

## 문서 명령

| 명령                   | 용도                                                             |
| ---------------------- | ---------------------------------------------------------------- |
| `npm run docs:dev`     | 라이브 리로드로 문서 사이트를 시작합니다                         |
| `npm run docs:build`   | 사이트를 빌드합니다. 끊어진 내부 링크가 있으면 빌드가 실패합니다 |
| `npm run docs:preview` | 빌드된 사이트를 로컬에서 제공합니다                              |

대부분의 참고 자료 페이지는 `docs/`의 파일을 포함합니다. `docs-site/` 아래의 페이지가 아니라 `docs/`의 파일을
편집하십시오. 포함된 파일의 PlantUML 다이어그램은 SVG로 렌더링되어 `docs-site/public/diagrams/` 아래에 커밋됩니다.

## 외부 디렉터리

스크립트와 테스트는 환경 변수를 통해 나란히 있는 체크아웃을 찾습니다. 기본값은 저장소 루트를 기준으로 한 상대
경로입니다. `tools/`와 `test/`만 이 변수를 읽으며, `src/`의 코드는 읽지 않습니다.

| 변수             | 기본값                         | 내용                                         |
| ---------------- | ------------------------------ | -------------------------------------------- |
| `ELK_SOURCE_DIR` | `../elk`                       | 고정된 커밋의 Eclipse ELK Java 소스          |
| `ELK_ORACLE_DIR` | `../elk-oracle`                | 분리된 워크트리와 빌드된 오라클              |
| `ELK_MODELS_DIR` | `../../eclipse-elk/elk-models` | 코퍼스 매니페스트에 고정된 elk-models 코퍼스 |

오라클 빌드에는 Maven 3.9 이상과 JDK 21(대체로 JDK 17)이 필요합니다. 오라클 절차는
[적합성](/ko/conformance)을 참고하십시오.
