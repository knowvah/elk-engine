# 貢献

まず[概要](/ja/guide/overview)と[翻訳ルール](/guide/translation-rules)（英語）を読んでください。固定コミットの Java が仕様です。迷ったときは Java を読んでください。

## ゲート

コミットの前に毎回実行してください。すべて通る必要があります。

| コマンド               | 検査内容                                                        |
| ---------------------- | --------------------------------------------------------------- |
| `npm run format:check` | Prettier による書式                                             |
| `npm run typecheck`    | TypeScript の型チェック（ネイティブの `tsc --noEmit`）          |
| `npm test`             | ゴールデンスイートを含む vitest スイート                        |
| `npm run coverage`     | 行・分岐・関数・ステートメントのカバレッジ 90% を求めるスイート |

Node 22 以降が必要です。依存関係は `npm ci` でインストールします。

## テストは変更不可

期待値は、実装が書かれる前に、オラクル、JVM ベクトル、または Java ソースから得ます（AD-13）。いったん書かれたアサーションは固定されます。テストが失敗するのは、実装が間違っているということです。

テストを通すにはアサーション、ベクトル、またはゴールデンを変更するしかない場合は、作業を止め、そのケースをミッションの決定ジャーナルに記録してください。テストを緑にするために、許容誤差を緩めたり、ケースを削除したり、参照を再生成したりしないでください。ゴールデン参照はスクリプトで再生成し、手作業では行いません。

## ワークフロー

1. フィーチャーブランチを作成します。例: `feature/<short-description>`。
2. コミットメッセージは [Conventional Commits](https://www.conventionalcommits.org) 形式で書きます。例: `feat(java): add JavaHashMap`。件名は小文字で、72 文字以内です。
3. `main` に対してプルリクエストを開きます。CI は、プルリクエストのタイトルを Conventional Commit として lint します。
4. コミットには署名が必要です。リポジトリのルールセットが要求します。
5. プルリクエストはマージコミットでマージします。

すべてのコードファイルに SPDX ヘッダー `// SPDX-License-Identifier: EPL-2.0` を付けます。フィットネステストがこれを強制します。依存関係は EPL-2.0 と互換でなければなりません。

## ドキュメントのコマンド

| コマンド               | 目的                                                       |
| ---------------------- | ---------------------------------------------------------- |
| `npm run docs:dev`     | ライブリロード付きでドキュメントサイトを起動する           |
| `npm run docs:build`   | サイトをビルドする。内部リンク切れがあるとビルドが失敗する |
| `npm run docs:preview` | ビルドしたサイトをローカルで配信する                       |

リファレンスページの多くは `docs/` のファイルを取り込んでいます。`docs-site/` 以下のページではなく、`docs/` のファイルを編集してください。取り込まれたファイル内の PlantUML 図は SVG にレンダリングされ、`docs-site/public/diagrams/` にコミットされます。

## 外部ディレクトリ

スクリプトとテストは、環境変数を通じて隣接するチェックアウトを見つけます。既定値はリポジトリルートからの相対パスです。これらの変数を読むのは `tools/` と `test/` だけで、`src/` のコードは決して読みません。

| 変数             | 既定値                         | 内容                                                        |
| ---------------- | ------------------------------ | ----------------------------------------------------------- |
| `ELK_SOURCE_DIR` | `../elk`                       | 固定コミットの Eclipse ELK Java ソース                      |
| `ELK_ORACLE_DIR` | `../elk-oracle`                | デタッチされた worktree とビルド済みのオラクル              |
| `ELK_MODELS_DIR` | `../../eclipse-elk/elk-models` | elk-models コーパス。コーパスのマニフェストで固定されている |

オラクルのビルドには Maven 3.9 以降と JDK 21（フォールバックは JDK 17）が必要です。オラクルの手順は[適合性](/ja/conformance)を参照してください。
