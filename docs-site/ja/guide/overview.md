# 概要

`@knowvah/elk-engine` は、Java 製のグラフレイアウトライブラリである [Eclipse Layout
Kernel](https://www.eclipse.org/elk)（ELK）の忠実な TypeScript 移植です。Java も WASM も使いません。レイアウトアルゴリズムはプレーンな TypeScript で再実装され、Java 実装に対して検証されています。

::: warning プレアルファ
レイアウトアルゴリズムはまだ移植されていません。リポジトリにあるのは、ツールチェーン、アーキテクチャ文書、検証用の足場、Java ランタイムのシムです。`src/index.ts` は公開されるものをまだ何もエクスポートしていません。アルゴリズムが追加される順序は[ロードマップ](/guide/roadmap)（英語）を参照してください。
:::

## Java が仕様である

固定された ELK コミット `8aaa3c145c2a18a38aabbc725aa3791ddc517a76` の Java ソースが正式な仕様です。移植はそれに忠実に従います。

- アルゴリズムの最適化や単純化は行いません。Java が冗長に見えても、その冗長さは残します。
- すべての分岐を移植し、TypeScript の制約で変更が必要な場合を除いてメソッドの境界を維持します。
- JUnit テストは、テスト対象のコードとともに移植します。
- ELK が依存する Java ランタイムの挙動（32 ビット整数演算、`HashMap` の反復順序、`Random` の系列）は、シムで再現します。[Java の基盤](/ja/guide/java-foundations)を参照してください。

[翻訳ルール](/guide/translation-rules)（英語）に、各 Java の概念が TypeScript にどう対応するかを一覧にしています。

## オラクルに対する検証

オラクルとは、固定コミットのデタッチされた git worktree でソースからビルドした上流の ELK です。移植の出力は、オラクルの出力と比較されます。

- ID、要素数、エッジセクションのトポロジー、ベンドポイント数、数値以外の値は、完全に一致しなければなりません。
- 数値の座標とサイズは、絶対許容誤差 `1e-6` の範囲内で一致しなければなりません。

厳選したオラクルの出力はゴールデン参照としてコミットされているため、テストの実行に JVM は不要です。完全な手順は[適合性](/ja/conformance)のページにあります。

## 公開コントラクト

公開 API は、ElkGraph オブジェクトモデルと `ElkGraphUtil` ファクトリになります。ELK JSON は I/O アダプターであり、コアモデルではありません。最初の npm 公開でこのインターフェースが固定されます。

## ランタイムの制約

- `src/` はブラウザで安全に動作します。Node の組み込みモジュール、`process.env` は使わず、ES モジュールのみです。
- ランタイム依存はありません。
