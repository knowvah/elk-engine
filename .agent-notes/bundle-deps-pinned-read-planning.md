# Planning notes: bundle-deps-pinned-read (issue #89, 2026-11-20)

## Observation: the regeneration check runs today with `../elk`, skips with the oracle worktree

- **Context**: Reproducing #89 while planning.
- **Finding**: `../elk` HEAD is the pin `8bca22f4` (since the 2026-11-18 pin move), so
  `npx vitest run test/architecture/module-boundaries.fitness.test.ts` gives 57 passed. With
  `ELK_SOURCE_DIR=../elk-oracle` (HEAD `cb2b6d54`, pin plus three patch commits) it gives 56 passed, 1 skipped. The
  oracle worktree contains the pin (`cat-file -e` and `merge-base --is-ancestor` succeed), and
  `git log 8bca22f4..HEAD -- 'plugins/*/META-INF/MANIFEST.MF'` there is empty.
- **Impact**: `../elk-oracle` is the ready-made off-`HEAD` checkout for proving the fix; no clone is needed.
- **Confidence**: High

## Observation: `git show <pin>:…MANIFEST.MF` equals the working-tree file

- **Context**: Checking that an object-store read cannot change the generated bytes (no eol filter).
- **Finding**: `git -C ../elk show 8bca22f4:<manifest> | cmp - ../elk/<manifest>` is equal for `core`,
  `alg.layered`, `graph.text` and `core.debug.grandom`; the deferred-bundles-adr mission checked all 16 through
  `git archive` byte for byte.
- **Impact**: Switching the reader leaves `bundle-deps.json` byte-identical.
- **Confidence**: High

## Observation: nothing tied the `bundle-deps.json` stamp to `ELK_COMMIT`

- **Context**: Deciding the CLI's commit (D1).
- **Finding**: `grep -rn ELK_COMMIT test` hits only corpus tests; the regeneration check reads at the file's own
  `elkCommit`, so a `--write` from a checkout at the wrong `HEAD` would have passed it once off-`HEAD` reads exist.
- **Impact**: The brief makes the CLI read the pin and adds a stamp-equals-pin case.
- **Confidence**: High
